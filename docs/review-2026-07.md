# Code, architecture & design review — July 2026

Full-repo review before the next roadmap rungs (ui, web, builder API).
Goals, as set by the lead: the project must be **simple to understand**, the
architecture **simple to grasp**, the docs **clear to read**, the code
**ergonomic** (no non-human constructions), **one class per file**, and the
recent increments (sync send, lifecycle, hot reload) simplified where they
grew awkward.

Like `roadmap.md`, this is a working document: strike items as they land,
delete the file when the cleanup is done.

**Method:** every source file, manifest, script, doc, and ADR read in full;
`cargo clippy --workspace --all-targets` run (clean on all bones-owned
crates; the 4 warnings are in vendored `pubsub-bus`). Findings are grouped
by kind and tagged with severity: **[bug]** wrong behavior vs. a documented
contract, **[design]** structural simplification, **[ergo]** code
ergonomics/readability, **[docs]** documentation, **[chore]** hygiene,
**[decided]** a call the lead already made during this review — the body
states the decision, no open options remain. Items 1.3–1.5, 3.3, 3.8, 4.3,
and 4.4 also carry inline decisions from the review questionnaire.
A proposed increment plan is at the end.

Overall verdict up front: the codebase is small (~2.6k LOC), well-tested,
and the kernel boundaries (bus / host / platform / renderer / runner /
lifecycle / logging) match `structure.md`. Nothing here is rotten. The
cleanup is about (1) two real contract bugs, (2) shrinking the one
overgrown file (`runner/src/engine.rs`, 611 lines), (3) removing duplicated
knowledge (tick codec, gfx payload schema, load-and-register ceremony,
extension build scripts), and (4) re-syncing docs that promise things the
code doesn't do yet.

## 1. Mistakes (contract violations and dead contract surface)

### 1.1 [bug] Faulted extensions stay reachable via direct `send` — and the failure is silent

`Supervisor::check` (core/runner/src/engine.rs:102-116) quarantines a
faulted extension by unregistering its **bus** endpoint only. Its
`Registry` entry is never removed, so a direct `send` to a quarantined
extension still resolves. `Host::respond` (core/host/src/lib.rs:199-213)
then short-circuits on `is_faulted()` and returns `None`, which
`Registry::call` (core/bus/src/lib.rs:120) converts to `Ok(vec![])` — the
caller receives a **successful empty reply** from a dead extension.

`messaging.md` promises the opposite: *"The outcome is always one of: a
reply, an error reply (target faulted, reloading, unknown), or a deadline
error. No request ends in silence."*

Fix: call `registry.remove(&extension.name)` in the quarantine branch, so
callers get `SendError::UnknownEndpoint`. Consider a dedicated error later,
but unknown-endpoint is honest and needs no contract change. While there,
note the related conflation: `Respond::respond` returning `None` means both
"chose not to reply" and "faulted" — after the registry fix the second case
can no longer be observed from outside, which resolves the ambiguity.

### 1.2 [bug] Extension logs are not tagged by extension

`architecture.md`: *"extensions log through a host import so all output
lands in one structured stream **tagged by extension**."* The
implementation hardcodes the category to `"extension"`
(core/host/src/lib.rs:74-82) even though `State.name` is right there. Two
extensions' logs are indistinguishable except by whatever prose the guest
happens to include (which is why every demo extension manually prefixes
`"hello extension:"`, `"level_demo ..."` — working around the missing tag).

Fix: `let category = &self.name;`. Then strip the manual name prefixes from
the demo extensions' log strings.

### 1.3 [design] `deadline_ms` and `SendError::Timeout` are contract surface that does nothing

`wit/core.wit:20` accepts `deadline-ms` and can return `timeout`, but the
host ignores the deadline entirely (core/host/src/lib.rs:97-103, TODO'd)
and nothing ever constructs `bus::SendError::Timeout`
(core/bus/src/lib.rs:37-43). An extension author reading the WIT will
reasonably rely on a deadline that silently doesn't exist.

The roadmap's own guardrail says contract churn is free pre-1.0 and to
break rather than shim. **Decision (questionnaire, 2026-07-12): remove** —
`deadline-ms` from the WIT, the `timeout` variant from `bus::SendError`
and the WIT, and `messaging.md`'s "every request carries a deadline"
wording, until a concurrent dispatcher makes them real. A superseding ADR
note on ADR-010 isn't needed — ADR-010 defines synchrony, not the deadline
parameter.

### 1.4 [design] `Envelope.correlation` is dead weight

`correlation: Option<u64>` (core/bus/src/lib.rs:9-15) is never set to
`Some` by any production code — replies are return values (ADR-010), so no
correlated message exists anywhere. It survives only because ADR-013 added
it speculatively. Every `Envelope` literal in the codebase (13 sites across
8 crates/examples) carries a `correlation: None` line of pure noise.

**Decision (questionnaire, 2026-07-12): delete the field.**
`messaging.md`'s envelope table drops the row. If an async pattern ever
needs it, adding a field is trivial and ADR-013's rationale is in history.
This also shortens every test fixture.

### 1.5 [bug-ish] Closing the window does nothing; the engine can only be killed

`translate_event` (core/platform/src/lib.rs:66-82) drops `Event::Quit`, and
`Engine::run` (core/runner/src/engine.rs:329-357) is `loop { }` with no
exit path. Result: clicking the window's close button is ignored; the only
way to stop `bones.exe` is Ctrl+C / kill. `design/platform.md` §Shutdown
specifies close-request-as-event + `shutdown()` calls + "the engine always
exits", and `Event::Stopped` (core/lifecycle/src/lib.rs:19) plus the WIT's
lack of a `shutdown` export are the visible holes.

Today this is in no roadmap entry and carries no `TODO` marker (the
code-conventions rule requires greppable `TODO`s for gaps). **Decision
(questionnaire, 2026-07-12): the minimal slice lands in this cleanup** —
platform translates `Event::Quit`, `Engine::run` exits its loop cleanly —
turning "demo you must kill" into "app that closes". The full shutdown
design (WIT `shutdown` export, `Stopped` events, close-request-as-event
per platform.md) becomes a roadmap rung (4.6).

### 1.6 [bug-edge] Hot-reload mtime polling misses two edge cases

`file_mtime` (core/runner/src/engine.rs:60-64) maps any error (including
*file deleted*) to `UNIX_EPOCH`, and the reload check is `mtime <=
extension.mtime → skip`. Consequences: (a) deleting an extension's file
leaves it running forever with no signal — defensible, but silent; (b)
replacing a file with an *older*-mtime one (restoring a backup copy) never
reloads. Neither deserves machinery, but (a) deserves a log line and both
deserve a sentence in `core/runner/README.md` so the behavior is a decision
rather than an accident.

### 1.7 [chore] One epoch-ticker thread leaks per `new_engine` call

`new_engine` (core/host/src/lib.rs:45-53) spawns an infinite ticker thread
per wasmtime `Engine`. Fine for the single engine in `run()`; in the test
suites every `Host::load`-based test leaks one. Harmless today, worth a
one-line doc note or a `OnceLock`'d shared engine in tests. Low priority.

## 2. Architecture & design simplifications

### 2.1 [design] `runner/src/engine.rs` (611 lines) is four components in one file

The file holds `Engine` (builder + run loop), `Supervisor` +
`TrackedExtension` (fault/reload sweeping), `SharedHost`/`SharedRenderer`
(bus-sharing wrappers), discovery helpers, and ~310 lines of tests. This is
the single worst offender against "classes in separate files" and "simple
to grasp". Proposed layout:

```text
core/runner/src/
├── lib.rs         # Runner (unchanged) + re-exports
├── engine.rs      # Engine builder/run only
├── supervisor.rs  # Supervisor + TrackedExtension
└── loading.rs     # SharedHost, attach/load helpers, find_wasm_files, derive_extension_name
core/runner/tests/
└── engine.rs      # the SDL/WASM integration tests (see 3.6)
```

`SharedRenderer` can live next to the renderer wiring in engine.rs or in
loading.rs — either is fine; the point is no file over ~200 lines of code.

### 2.2 [design] The load-register-subscribe-insert ceremony is duplicated

The same five-step dance — `Host::load` → `requested_topics()` → wrap in
`SharedHost` → `bus.register` + `subscribe` each topic → `registry.insert`
— appears in `Engine::build` (engine.rs:242-263) and again in
`Supervisor::check`'s reload arm (engine.rs:119-149), with the fault-prone
requirement that the two stay in lockstep (1.1 above is exactly a case
where one path forgot a step's mirror image). Extract one function:

```rust
fn attach_extension(bus, registry, wasm_engine, path, name, logger)
    -> wasmtime::Result<(Endpoint, SharedHost)>
```

Both call sites shrink to a match on its result. This also makes the fix
for 1.1 (registry removal on quarantine) reviewable next to its inverse.

### 2.3 [design] `Engine::build`'s 4-tuple return

`build()` returns `(Runner, Option<Platform>, Option<Arc<Mutex<Renderer>>>,
Supervisor)` behind `#[allow(clippy::type_complexity)]`
(engine.rs:228-231) — the allow-attribute is the code admitting the
signature is not human-friendly. Return a named struct instead:

```rust
pub struct BuiltEngine {
    pub runner: Runner,
    pub platform: Option<Platform>,
    pub renderer: Option<Arc<Mutex<Renderer>>>,
    pub supervisor: Supervisor,
}
```

Call sites gain field names, the allow goes away, and future additions
(module registry, services) don't churn every destructuring.

### 2.4 [design] `Supervisor` needs no interior mutability

`Supervisor.tracked` is `Mutex<Vec<...>>` solely so `check(&self)` can
mutate (engine.rs:90, 102-104). Nothing shares a `Supervisor` across
threads — `run` owns it, tests own it. Make it `tracked: Vec<TrackedExtension>`
and `check(&mut self)`; one lock and one `.lock().unwrap()` disappear, and
the type stops implying concurrency that doesn't exist.

### 2.5 [design] The `core/tick` codec is defined twice; the gfx payload schema is defined twice

- `TICK_TOPIC` + dt decoding exist in `runner` (core/runner/src/lib.rs:7-17,
  public) and again privately in `host` (core/host/src/lib.rs:19,55-61) —
  copy-paste including the doc comment.
- The `gfx/draw-sprite` byte layout is hand-built in
  `extensions/sprite_demo/src/lib.rs:21-31` and hand-parsed in
  `core/renderer/src/lib.rs:60-71`; nothing but discipline keeps the field
  orders aligned, and the same will happen for every future command and
  every future extension.

Both are the same disease: **the core message vocabulary has no home**.
Per the 2.7/2.9 decisions the home is **`shared/bones-messages`**: one
standalone crate (workspace-excluded like `buffer_rw` today, so guests can
depend on it too) that absorbs `buffer_rw`'s `Reader`/`Writer` and owns
typed topics plus payload encode/decode for core-defined messages —
tick, lifecycle, gfx commands. Then: renderer parses with it, sprite_demo
builds with it, host and runner use one `Tick` contract, and
`core/lifecycle` shrinks to its `publish` helper. This directly
serves ADR-001 ("any language must reproduce the bytes") by making the
Rust reference codec importable on both sides of the boundary.

### 2.6 [decided] pubsub-bus stays (lead's constraint) — modify it upstream to remove the tax

**Constraint set during review: pubsub-bus is a must-use, and it may be
modified to cover bones' needs** (same owner; vendored as a submodule, so
bones can track a branch while changes land). That closes the
keep-vs-inline question — what remains is making the dependency earn its
place instead of being routed around. Today bones bypasses most of it:
`is_subscribed_to` always returns `true` and all topic matching happens
inside bones' `Adapter` (core/bus/src/lib.rs:139-155), with a `()` TopicId
and an extra bones-side `Arc` because `EventBus` doesn't expose `Clone`.
The `Subscriber: Send + Sync` bound cascades upward into `Handler: Send +
Sync` (bus), the `SendWrapper` panic-guard around `Renderer` (renderer),
and is part of why `Host` carries an inner `Mutex`.

Upstream wishlist, in impact order — agree it first, then implement in
`vendor/pubsub-bus` and bump:

1. **Move topic matching out of the subscriber lock.** Let the bus store
   each subscriber's patterns *next to* the `Arc<Mutex<dyn Subscriber>>`
   (subscribe/unsubscribe APIs on the bus, prefix-wildcard matching
   included), instead of locking every subscriber's `Mutex` just to ask
   `is_subscribed_to` per message. This removes bones' whole `Adapter`
   filtering layer, the `()` TopicId hack, and the
   every-endpoint-locked-per-message cost — and it's the piece ADR-015
   identified as the crate's most exposed shape.
2. **Relax the `Subscriber` bound to `Send`** (or make the bound generic).
   `Arc<Mutex<T>>` is `Send + Sync` when `T: Send`, so pubsub-bus's own
   threading model doesn't need `Sync` on the subscriber itself. `Handler`
   then relaxes to `Send`, which shrinks the justification comments in
   host/renderer. (`SendWrapper` on `Renderer` survives even this — SDL's
   thread affinity is real and `Send` is the honest minimum for a bus that
   may one day dispatch off-thread — but it becomes the *only* remaining
   wrapper, with a true constraint behind it.)
3. **`impl Clone for EventBus`** (it is already Arc-backed internally) —
   bones' own wrapping `Arc` in `Bus` disappears
   (core/bus/src/lib.rs:186-191).
4. Housekeeping: the 4 clippy warnings (`Default` impls, `unnecessary_unwrap`,
   `type_complexity`) — `cargo clippy --fix` covers half.

Two things stay bones-side **permanently, by design**, and must not be
mistaken for removable workarounds: **deferred dispatch** (ADR-015 —
reentrant publish is a structural hazard regardless of any upstream fix)
and **`SharedHost`** (one `Host` instance genuinely shared between bus
registration, registry registration, and the supervisor — inherent
sharing, not a pubsub-bus artifact). Record the wishlist outcome as a
short ADR superseding the workaround rationale in ADR-013 that each
upstream change retires.

### 2.7 [decided] Crate naming: `bones-*` workspace plus a `bones` facade crate

`bus`, `host`, `app`, `logging`, `platform`, `renderer`, `runner`,
`contract`, `lifecycle` are unprefixed generic names — workable as private
workspace members, colliding the moment the library distribution
(design/modules.md) is consumed as a git dependency.

**Decision (review discussion, 2026-07-12):** keep the crate-per-component
workspace — the Cargo dependency graph is what makes structure.md's
dependency rules compiler-enforced, so merging into one crate is off the
table — rename with a flat `bones-` prefix, and add a thin **`bones`
facade crate** as the only name embedders depend on.

- Kernel: `bones-bus`, `bones-host`, `bones-contract`, `bones-platform`,
  `bones-runner`, `bones-lifecycle`, `bones-logging`. No `core` infix — it
  adds a hierarchy level with no information; the `core/` *directory*
  stays as-is.
- Modules: `bones-renderer`, `bones-ui`, `bones-web`. No `module` infix —
  ADR-011 makes the module/extension distinction invisible on the bus;
  names shouldn't bake it in.
- Shared guest+host: `buffer_rw` → `bones-messages` (see 2.5 and ADR-016).
- Facade: `bones` re-exports `Engine`, the module traits, and forwards
  feature flags (`bones = { git = "…", features = ["renderer", "ui"] }`).
  The engine.rs TODO about `bones::Engine` resolves here. `app` switches
  to depending on `bones`, which keeps the facade honest — if the app
  can't do it through the facade, embedders can't either.

Rejected: a single `bones-core` exposing everything — it would turn the
compiler-enforced dependency rules into convention, put SDL/wry behind
feature flags of the crate every embedder's kernel sits in, and still
couldn't absorb the guest-side vocab crate (which must compile to
`wasm32-wasip2` without wasmtime/SDL). Record the naming decision as an
ADR when the rename lands (increment 8).

### 2.8 [ergo] Supervisor polls file mtimes 120×/sec per extension

`run` calls `supervisor.check()` twice per iteration (engine.rs:339,346)
and each check stats every tracked file. At 60 Hz with a handful of
extensions that's thousands of syscalls/sec for a change that happens
once a minute during live editing. Cheap but pointless: throttle the
*mtime* half of `check` to e.g. 4 Hz (the fault half stays every-call —
it's just an atomic load). One `Instant` field in `Supervisor` suffices.

### 2.9 [decided] Repository layout stays flat — no root `src/`, `vendor/` stays top-level

**Decision (review discussion, 2026-07-12):** the top level keeps its
current shape. A repo-root `src/` signals "this repo is one crate" in
Rust, and grouping members (the idiom would be `crates/`, not `src/`) buys
nothing here: `core/` + `extensions/` + `wit/` + `docs/` already mirrors
structure.md one-to-one. `vendor/` in particular must stay outside any
source grouping — it marks the ownership boundary (upstream-tracked
submodule, changed only via the 2.6 wishlist process), and folding it into
the project's own source tree would erase exactly that signal.

The only layout moves are the ones already listed: delete `hello_world/`
(5.1) and home the shared guest+host crate(s) under `shared/` —
`shared/bones-messages` per 2.5/2.7 and ADR-016. structure.md's source-layout tree gains
`shared/` and `vendor/` entries (4.4).

### 2.10 [design] `Respond` asymmetry is fine — but say so

`Handler::handle(&mut self)` vs `Respond::respond(&self)` looks
inconsistent until you see that `Registry::call` must clone the target
`Arc` out of the map and invoke it *outside* the registry lock. That
rationale lives nowhere. One sentence on the `Respond` trait doc
(core/bus/src/lib.rs:29-33) prevents the next reader from "fixing" it.

## 3. Code ergonomics & file layout

### 3.1 [ergo] Doc comments have grown past the comment-brevity rule

The repo's own convention (agents/AGENTS.md: 1–2 lines unless a non-obvious
constraint demands more) is violated most in the recent increments —
e.g. `Engine::run`'s 20-line doc (engine.rs:307-328), `Engine::build`'s
14-line doc (engine.rs:214-227), `Supervisor`'s type+method docs
(engine.rs:77-101). Much of this is *why-this-is-correct* narration
(supervision timing, deferred-dispatch echoes) that belongs in the design
docs it already cites, not restated at every call site. Suggested pass:
keep the constraint sentences ("check runs before and after step because
…" compressed to one line each), delete the rest. Target: no doc comment
over ~4 lines outside genuinely tricky spots (the `SendWrapper` and
epoch-deadline notes are the good kind — keep those).

### 3.2 [ergo] Verb-first naming stragglers

Per the code conventions: `file_mtime` → `read_file_mtime`
(engine.rs:60), `tick_dt` → `parse_tick_dt` or `read_tick_dt`
(runner/src/lib.rs:11, host/src/lib.rs:55 — merges anyway per 2.5).
Everything else checks out (builder methods are the sanctioned exception).

### 3.3 [ergo] `Engine::builder()` returns an `Engine` that is really a config

One type plays builder-being-configured and engine-being-run
(engine.rs:161-177). It works, but `Engine::builder()` returning `Engine`
reads oddly, and half the fields (`window`, `renderer_enabled`) are
consumed by `build` while others survive into `run`. **Decision
(questionnaire, 2026-07-12): rename to `Engine::new()`** — accept that
`Engine` is configured fluently, drop the "builder" pretense, no separate
builder type. `modules.md`'s composition-root sketch updates to match.

### 3.4 [ergo] `Platform::poll_events(bus, sender)` — the `sender` parameter is ceremony

Every caller passes `"platform"` (engine.rs:336, examples, tests). The
component's bus identity isn't the caller's decision; hardcode a
`pub const SENDER: &str = "platform"` inside the crate and drop the
parameter (keep an internal seam if a test truly needs to vary it — none
does today).

### 3.5 [ergo] Renderer silently swallows unknown `gfx/*` topics

`Command::decode` returns `Ok(None)` for an unrecognized `gfx/…` topic and
`handle` returns silently (core/renderer/src/lib.rs:147-151). A typo'd
topic in an extension (`gfx/draw-spirte`) produces zero feedback anywhere.
Since the renderer subscribes to `gfx/*`, an unmatched topic within that
prefix is always a caller error: log it (warn, or debug if spam is a
concern). Non-gfx topics can't reach it, so the check is free.

### 3.6 [ergo] Integration tests masquerading as unit tests

`runner`'s test module (engine.rs:381-691) opens real SDL windows, loads
real prebuilt `.wasm` fixtures, and copies files around temp dirs — these
are integration tests and belong in `core/runner/tests/`, which also
removes ~310 lines from engine.rs and makes `cargo test -p runner --lib`
fast and fixture-free. Only `tick_hz_defaults_to_60_and_is_overridable`
touches private fields; keep that one in-file. Same consideration applies
to `host`'s wasm-loading tests (host/src/lib.rs tests) if the split feels
worth it there too — lower value, since host has no SDL dependency.

While there: the "build extensions/... first" expectation strings are good,
but the knowledge of *which* fixtures exist is scattered across four
`const`s in two crates. A tiny `tests/fixtures.rs` helper (or a repo task
that builds all fixtures — see 5.3) would centralize it.

### 3.7 [ergo] `Config::load(path: &str)` and stringly errors

Minor: `impl AsRef<Path>` is the idiomatic parameter
(core/app/src/config.rs:34), and `core/platform`'s `Result<_, String>`
errors are fine at this scale but worth a note that they'll want a real
error type before the library distribution ships. No action needed now
beyond agreement.

### 3.8 [ergo] The app can't be configured headless

`core/app/src/main.rs:20-26` always calls `.window(...)`; `bones.toml` has
a `renderer` toggle but no way to say "no window" — while the engine
builder itself supports exactly that. **Decision (questionnaire,
2026-07-12): add the headless toggle** — `window = false` in `bones.toml`.
Since `.renderer()` requires a window, `window = false` +
`renderer = true` is a startup error (consistent with the config's
no-silent-no-op stance), and `renderer` keeps its current default.

## 4. Documentation

### 4.1 [docs] Root README is below the project's own bar

`README.md` is 15 lines with three typos ("extention", "prototypiong",
"applicaiton"), no link to `docs/index.md`, no build/run quickstart, and no
statement of current status. Both agent flows and humans are told to start
at the README; today it dead-ends. Suggested shape (stays under a page):
what bones is (2 sentences), status ("kernel + renderer + hot reload work
today; ui/web are next — see docs/roadmap.md"), quickstart (`pwsh dist.ps1`
→ `dist/bones.exe`; or `cargo run -p app` + build an extension), pointer to
`docs/index.md` for everything else.

### 4.2 [docs] messaging.md promises three things the system doesn't do

- **Deadlines**: "Every request carries a deadline … or a deadline error" —
  see 1.3; rewrite alongside whichever way that decision goes.
- **Flow control / queue budgets**: "bounded inbound queue and per-frame
  publish allowance … Budget violations fault the extension" — ADR-007's
  queue budget is entirely unimplemented (only the time budget exists), and
  no roadmap rung tracks it. Either add it to the roadmap or mark the
  paragraph as not-yet-implemented; today the doc reads as description of
  behavior that doesn't exist.
- **Correlation**: the envelope table ties `correlation` to direct
  messages, but direct sends never produce envelopes at all (ADR-010 made
  them plain calls via `Registry`). See 1.4; if the field is deleted the
  row goes with it, and the request/reply sequence diagram should stop
  implying bus-mediated correlated replies.

### 4.3 [docs] extensions.md describes a manifest and duplicate-check that don't exist

"packaged with a small manifest giving its **name** and **version**. The
name must be unique per engine instance; the host rejects duplicates at
load" — reality: no manifest (name = file stem, engine.rs:375-379) and no
duplicate rejection anywhere (`Registry::insert` silently overwrites;
`Bus::register` doesn't check names). Within one extensions directory file
stems are unique by construction, so this is currently unreachable — but
the doc states a contract. **Decision (questionnaire, 2026-07-12):
implement the uniqueness check** — registration (bus and registry) rejects
a duplicate endpoint name with an error, making the doc's claim true. The
manifest half still gets the reality rewrite (name = file stem; manifests
deferred to a future ADR). Same doc
lists `init(config)` and `shutdown()` in the contract sketch; the real WIT
has `init()` and no shutdown (see 1.5). The doc says signatures are
concept-level, which covers `config`, but `shutdown` is a real gap the doc
presents as present.

### 4.4 [docs] structure.md's kernel table over-states runner and logging

- runner: "module & service registries, builder API" — no module or service
  registry exists (TODO'd in engine.rs; roadmap rung 3). The table row
  reads as current.
- logging: "per-extension tagging, drop counters" — tagging is broken (1.2)
  and drop counters don't exist (they belong to the unimplemented queue
  budget, 4.2).

structure.md is allowed to describe target shape, but it doesn't say which
cells are aspirational. **Decision (questionnaire, 2026-07-12): the
legend** — one line ("responsibilities in *italics* are not yet built"),
aspirational cells italicized and kept visible.

Also: the source-layout tree omits `buffer_rw/` (a real, load-bearing
shared crate) and `vendor/` while showing `ui/`/`web/` (which don't exist
yet). Add `shared/` (bones-messages, per 2.5/2.9 and ADR-016) and `vendor/`, and mark
ui/web as planned.

### 4.5 [docs] Per-crate READMEs partially restate their crates' doc comments

The crate READMEs are good — but several (host, runner especially) are
near-transcripts of the module docs, which means every behavior change is
now written three times (code doc, README, design doc). Per the docs
policy's altitude test, consider trimming crate READMEs to: one-paragraph
responsibility + pointers (design doc, key types) and let rustdoc own API
detail. Not urgent; flagged because the runner README already drifted into
step-by-step `run()` semantics that engine.rs also narrates (see 3.1 — fix
both by deleting one).

### 4.6 [docs] roadmap.md is missing the shutdown rung

Per 1.5 and 4.2: clean shutdown (Quit handling, `shutdown` export,
`Stopped` event) and the ADR-007 queue budget are documented designs with
no code and no roadmap entry — the exact situation the roadmap's
maintenance rule exists to prevent. Add them (or explicitly de-scope in
the design docs).

## 5. Repo & build hygiene

### 5.1 [chore] Delete `hello_world/`

A `println!("Hello, world!")` binary crate, first workspace member in
`Cargo.toml:3`. Scaffolding leftover; nothing references it. Delete the
directory and the member entry.

### 5.2 [chore] Five identical extension build scripts

`extensions/*/build.ps1` are byte-identical except the final echoed
filename. Every new extension copies one more. Replace with a single
`extensions/build.ps1 [name]` (no arg = build all), and make each
extension's README say `pwsh ../build.ps1 hello`. `dist.ps1:57-73` then
loops with one call instead of per-directory scripts. (Per the
fix-the-script-not-around-it principle, change the real scripts, don't add
wrappers.) The per-extension `[workspace]` + own `Cargo.lock` setup is
*correct* (guests need a different target and must be copyable), so keep
that — this is only about the scripts.

### 5.3 [chore] Test fixtures require manual pre-builds with no single entry point

Running `cargo test -p runner` cold fails until you've run four separate

`test.ps1` (or extend `dist.ps1` with a `-Fixtures` switch) that builds all
extensions then runs `cargo test --workspace`, and mention it in the root
README. One command from clean clone to green tests is the bar.
